# Reminder For ADHD

[English](README.md) | 日本語

カレンダーの予定の時間になったら、画面の下 1/4 へ予定を大きく表示する macOS のメニューバーアプリ。ADHD 向けに「了解」を押すまで消えない。

Mac に同期されたカレンダーなら何でも使える。Google カレンダー・iCloud・Exchange / Microsoft 365・Yahoo! などの CalDAV のカレンダー・「このMac」のローカルのカレンダー・照会しているカレンダーに対応する。

## 機能

- 予定の時間に、全ディスプレイ・全 Space (全画面アプリの上も含む) にパネルを表示する
  - 通知するタイミングはメニューで「5分前」「1分前」「開始時刻」から複数選べる (既定は開始時刻だけ。最後の1つは外せない)
  - 「了解」はそのタイミングの分だけ。後のタイミングではまた表示する
  - 「参加する」を押した予定は、後のタイミングでも表示しない
  - ボタン: `参加する` (Meet / Zoom / Teams の URL があるとき) / `了解` / `5分後にもう一回`
  - キーボードのフォーカスは奪わない
  - 開始から30分以内なら、スリープ明けなどで遅れても表示する
  - 終日の予定・キャンセルされた予定・自分が辞退した予定は表示しない
- 音声出力がミュートまたは音量 0 のとき、メニューバーのアイコンとパネルで知らせる。パネルからミュートを解除できる (音量は変えない)
- 通知するカレンダーをメニューで選べる (アカウントごとに表示。最初はすべてオフで、新しく増えたカレンダーもオフ。1つも選んでいないときはメニューバーのアイコンとメニューで知らせる)
  - アカウントごとに「すべてオン / すべてオフ」でまとめて切り替えられる
  - 今日の予定があるカレンダーには「今日 N件」と出す。見出しには選んだ数を「(2/15)」のように出す
- 今日の予定には、どのカレンダーの予定かも出す
- メニューバーのアイコンを押すとパネルが開く。一番上に次の予定まであと何分かを大きく出し、その下に今日の予定・通知が届かない原因 (ミュート・カレンダー未選択・アクセス未許可) とその場で直すボタン・通知するタイミング・通知するカレンダー・テスト表示・終了を並べる。下にバージョンを表示する
- `/Applications` に置くと、初回起動時にログイン項目へ登録される

## セットアップ

1. **Mac にカレンダーのアカウントを追加する**
   システム設定 → インターネットアカウントで、アカウント (Google・iCloud・Exchange など) を追加して「カレンダー」をオンにする。
2. **Mac に同期するカレンダーを確かめる**
   アプリのメニューで選べるのは、Mac に同期されたカレンダーだけ。Google の場合、共有カレンダーなどがメニューに出てこないときは、[Google の同期設定](https://calendar.google.com/calendar/syncselect) でチェックを入れる。
3. **同期の間隔を決める**
   カレンダー.app → 設定 → アカウント → (追加したアカウント) →「カレンダーの更新」。おすすめは「5分ごと」。
4. **ビルドしてインストールする** (XcodeGen が必要: `brew install xcodegen`)

   ```sh
   make install   # Release ビルドを /Applications/Reminder For ADHD.app にコピーして起動する
   ```

   初回起動時にカレンダーへのアクセス許可を求められる。許可したら、メニューの「通知するカレンダー」で通知してほしいカレンダーにチェックを入れる (最初はすべてオフなので、選ぶまで何も通知されない)。

   ログイン項目への登録に失敗したときの記録は次で見られる。

   ```sh
   log show --predicate 'subsystem == "jp.co.asaichi.reminder"' --last 10m
   ```

### カレンダー.app は使わなくてよい

このアプリは Google などのカレンダーのサービスへ直接取りに行かず、macOS が裏で同期した予定を読む。同期はカレンダー.app を起動していなくても行われるので、ふだんカレンダー.app を使う必要はない。予定の追加や編集は、ブラウザやスマートフォンの Google カレンダーなど、いつも使っているところで行えばよい。

カレンダー.app を開くのは、予定が Mac に同期されているかを確かめるときと、同期の間隔を変えるときだけ。

## 開発

```sh
make generate  # project.yml から Reminder.xcodeproj を生成する
make build     # Debug ビルド
make run       # Debug ビルドを起動する (メニューの「テスト表示」でパネルを確認できる)
make test      # 単体テスト
```

`.xcodeproj` は生成物なので git に入れない。

### 署名

既定では証明書なし (ad-hoc) で署名する。その場合、ビルドし直すたびにカレンダーへのアクセス許可を求められることがある。

自分の証明書で署名するときは `Config/Signing.local.xcconfig.example` を `Config/Signing.local.xcconfig` にコピーして、証明書とチーム ID を書く (このファイルは git に入れない)。

## 構成

| ディレクトリ | 役割 |
|---|---|
| `Reminder/Core` | 通知の判定・会議 URL の抽出・表示用の文字列。Foundation だけに依存し、単体テストの対象 |
| `Reminder/Calendar` | 予定の取得元 (`CalendarSource`) と EventKit 実装 |
| `Reminder/Audio` | CoreAudio によるミュート・音量の監視 |
| `Reminder/Overlay` | 通知パネル (NSPanel + SwiftUI) |
| `Reminder/App` | エントリポイント・メニューバー・タイマー・ログイン項目 |

### バッテリーへの配慮

定期的なポーリングはしない。予定を読み直すのは次のときだけ。

- カレンダーの同期が終わったとき (`EKEventStoreChanged`)
- 次に表示が変わる時刻 (通知の開始・予定の終了・「もう一回」の時刻)
- スリープからの復帰・日付の変更・時計やタイムゾーンの変更
- 変更通知を取りこぼしたときのための、30分に1回の読み直し (遅れてもよい設定にしてある)

App Nap は通知の2分前から通知を出すまでだけ止める。ミュートの状態も CoreAudio の変更通知でだけ読み直す。
